# 📋 Event-Driven Kanban-система (Enterprise Task Manager)

Высокопроизводительная Kanban-система корпоративного уровня с архитектурой, управляемой событиями (**Event-Driven Architecture**), разработанная в соответствии с методологией **Feature-Sliced Design (FSD)**.

Система обеспечивает реальное время синхронизации данных между всеми подключенными клиентами, поддерживает отказоустойчивую обработку потоков задач через очередь сообщений **RabbitMQ**, а также выполняет интеллектуальную фоновую автоматизацию с помощью событийно-ориентированного движка правил.

---

## 🏛️ Архитектура системы

Проект спроектирован по методологии **Feature-Sliced Design (FSD)**, разделяющей кодовую базу на строго изолированные слои, слайсы и сегменты:

```
web-engineers-rep/
├── server/                    # ⚙️ Бэкенд слой (Nitro Engine / Node.js)
│   ├── api/                   # REST API Эндпоинты (Задачи, Колонки, Логи)
│   ├── models/                # Схемы данных MongoDB / Mongoose (Task, Column, Rule)
│   ├── plugins/               # Плагины Nitro (Инициализация WebSocket, RabbitMQ Consumer, MongoDB)
│   └── utils/                 # Утилиты (RabbitMQ Publisher, Валидаторы)
├── stores/                    # 🍍 Глобальные хранилища состояния (Pinia Store - Kanban)
├── widgets/                   # 🧩 Крупные функциональные блоки интерфейса
│   ├── sidebar/               # Сайдбар навигации с динамическими проектами
│   ├── header/                # Шапка с центрированным поиском и управлением задачами
│   ├── tasks-table/           # Интерактивная доска со столбцами задач
│   └── dashboard-stats/       # Дашборд аналитики спринта для активного проекта
├── features/                  # ✨ Интерактивные фичи (Создание задач)
├── shared/                    # 🛠️ Переиспользуемые утилиты, UI-компоненты и стили
│   ├── ui/                    # Базовые UI элементы (Модалки, Кнопки, Тосты)
│   └── lib/                   # Переиспользуемые библиотеки (Аудиоэффекты)
├── assets/                    # 🎨 Глобальные стили и CSS Glassmorphic темы
└── pages/                     # 📄 Страницы приложения (Главная доска, Консоль Администратора)
```

## 🛠️ Технологический стек

### Фронтенд (Client-side)
- **Nuxt 3 (Vue 3)** — фреймворк для создания сверхбыстрых SPA приложений с использованием Composition API и TypeScript.
- **Pinia** — реактивное хранилище состояния для кэширования данных доски, поиска и активных проектов.
- **Socket.io-client** — двухсторонняя real-time синхронизация событий.
- **Glassmorphism CSS Architecture** — премиальный дизайн с эффектом матового стекла, радиальными неоновыми подсветками и динамическими переходами при наведении.

### Бэкенд (Server-side)
- **Nitro Engine** — высокопроизводительное серверное ядро Nuxt 3.
- **Mongoose & MongoDB** — объектно-реляционное моделирование и нереляционная база данных для хранения задач, колонок и системных правил.
- **RabbitMQ (`amqplib`)** — брокер сообщений для асинхронного выполнения фоновых задач, обеспечивающий надежность доставки и обработки сообщений.
- **Socket.io** — WebSocket сервер, интегрированный в Nitro-контейнер для мгновенного обновления интерфейса всех пользователей без опроса API (Zero-Polling).

## 🔄 Событийная модель реального времени (Real-time & Event-Driven)

Интеграция очередей сообщений и WebSockets обеспечивает полную консистентность данных и отказоустойчивость:

```
[Пользователь] 
      │
      ▼ (HTTP POST / PUT)
[REST API] ──► [Сохранение в MongoDB]
      │
      ├──► [Socket.io Emit] ───────────────► [Все подключенные пользователи] (Мгновенное обновление UI)
      │
      ▼ (Издание события в очередь)
[RabbitMQ Publisher] ──► [Очередь: kanban_events] (Гарантированная доставка)
                                 │
                                 ▼ (Асинхронное потребление)
                       [RabbitMQ Consumer] ──► [Движок правил / Автоматизация]
                                                         │
                                                         ▼ (Приоритет URGENT)
                                               [Обновление задачи в БД]
                                                         │
                                                         ▼ (WebSocket оповещение)
                                               [Всплывающий Toast Уведомления]
```

### ⚡ Интеллектуальный движок автоматизации (Rule Engine):
- **Событие `task.created` / `task.updated`**: Фоновый обработчик проверяет теги задачи. При обнаружении тега `URGENT` приоритет задачи автоматически повышается до максимального значения `Urgent` в MongoDB.
- **Real-time Оповещения**: При автоматическом срабатывании правил система генерирует WebSocket-событие `notification:urgent`, мгновенно отображая на экранах всех пользователей всплывающий тост-уведомление со звуковым сопровождением.
- **Отказоустойчивость (Self-Healing Connection)**: Подключения к RabbitMQ защищены слушателями ошибок `conn.on('error')` и закрытия `conn.on('close')`. При сбое брокера приложение продолжает работу в автономном режиме, восстанавливая связь при первой возможности.

## ⚙️ Настройка и запуск локально

### 1. Требования к окружению
Перед запуском убедитесь, что на вашей локальной машине установлены:
- **Node.js** (версии 18.x или выше)
- **MongoDB Server** (порт по умолчанию: `27017`)
- **RabbitMQ Server** (порт по умолчанию: `5672`)

### 2. Конфигурация переменных окружения
Создайте файл `.env` в корневой директории проекта и задайте необходимые адреса подключения:
```env
MONGODB_URI=mongodb://localhost:27017/Kanban
RABBITMQ_URL=amqp://localhost:5672
```

### 3. Установка зависимостей
Установите необходимые NPM-пакеты:
```bash
npm install
```

### 4. Запуск в режиме разработки (Development)
Запустите локальный сервер разработки:
```bash
npm run dev
```
Приложение будет доступно по адресу: [http://localhost:3000](http://localhost:3000).

## 🚀 Развертывание в продакшене (Production)

Для деплоя приложения на удаленном сервере (VPS/VDS) рекомендуется использовать контейнеризацию **Docker** или менеджер процессов **PM2**.

### Вариант А: Запуск через Docker Compose (Рекомендуется)
Создайте файл `docker-compose.yml` в корне проекта:
```yaml
version: '3.8'

services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - MONGODB_URI=mongodb://mongodb:27017/Kanban
      - RABBITMQ_URL=amqp://rabbitmq:5672
    depends_on:
      - mongodb
      - rabbitmq

  mongodb:
    image: mongo:latest
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db

  rabbitmq:
    image: rabbitmq:3-management
    ports:
      - "5672:5672"
      - "15672:15672"

volumes:
  mongo_data:
```
Запустите всю инфраструктуру одной командой:
```bash
docker-compose up -d --build
```

### Вариант Б: Сборка и запуск через PM2
1. Соберите оптимизированный production-билд приложения Nuxt:
   ```bash
   npm run build
   ```
2. Запустите собранный бэкенд-сервер через PM2:
   ```bash
   pm2 start .output/server/index.mjs --name "kanban-enterprise"
   ```

## 💎 Реализация ключевых критериев оценки кейса

- **Функциональность**: Полноценное управление задачами (фильтрация, поиск, исполнители, дедлайны) с динамическими проектами.
- **Real-time**: Абсолютная синхронизация изменений по протоколу WebSockets (Socket.io) без задержек.
- **Автоматизация**: Обработчик событий в бэкенд-очереди RabbitMQ с интеллектуальным поднятием приоритетов и автоматической рассылкой уведомлений.
- **Интерфейс**: Премиальный пользовательский дизайн в стиле **Sapphire & Hologram UI** с применением передовых эффектов стекломорфизма (Glassmorphism), градиентными подсветками и звуковыми эффектами.
- **Надежность**: Самовосстанавливающиеся соединения с брокерами данных, транзакционная обработка и дедубликация.
